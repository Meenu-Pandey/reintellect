# Design Document: ReIntellect AI-Powered Store Intelligence Platform

## Overview

ReIntellect is a monolithic AI-powered Store Intelligence Platform that transforms raw CCTV footage into real-time retail analytics. The platform runs as two processes: a Python backend (detection pipeline + event engine + FastAPI) and a React/Vite frontend. All inter-component communication uses in-process `asyncio.Queue` objects — no external message brokers.

The system is optimised for the Purplle Tech Challenge 2026 scoring criteria: clean architecture, comprehensive testing, containerised deployment, and real-time analytics accuracy.

### Key Design Decisions

- **Monolithic Python backend**: Detection pipeline, event engine, and FastAPI API share a single process and communicate via `asyncio.Queue`. This eliminates network overhead, simplifies deployment, and avoids distributed systems complexity.
- **SQLite + aiosqlite**: Sufficient for hackathon scale; async I/O prevents blocking the event loop.
- **`visitor_id` vs `track_id`**: `track_id` is ByteTrack-internal and never exposed in the public API. `visitor_id` is assigned at `ENTRY` confirmation and is the stable public identifier.
- **Client-supplied `event_id`**: Ingestion is idempotent by `event_id` (UUID v4 supplied by the pipeline, not generated by the server).
- **FastAPI native WebSockets**: No external pub/sub; the API layer maintains an in-memory connection registry per store.

## Components and Interfaces

### Detection Pipeline Architecture

The `DetectionPipeline` runs as an `asyncio` task inside the backend process. It reads frames from one or more camera feeds (RTSP streams or video files), runs YOLOv8n inference, applies ByteTrack, and pushes `TrackFrame` objects onto an `asyncio.Queue`.

```
Camera Feed(s)
     │
     │  raw frames (numpy arrays)
     ▼
┌────────────────────────────────────────────────────────┐
│  DetectionPipeline                                     │
│                                                        │
│  1. Frame reader (cv2.VideoCapture / RTSP)             │
│     - Reads at configured FPS (≥10 fps per camera)     │
│     - On feed loss: logs interruption, polls for       │
│       reconnect, preserves active track state          │
│                                                        │
│  2. YOLOv8n inference                                  │
│     - Model: yolov8n.pt (person class only, class=0)   │
│     - Confidence threshold: 0.5                        │
│     - Min bounding box height: 50px                    │
│     - Device: CUDA if available, else CPU              │
│     - Detections below threshold → discarded           │
│                                                        │
│  3. ByteTrack multi-object tracker                     │
│     - Assigns persistent track_id per person           │
│     - Re-associates tracks lost < 30 frames            │
│     - New track_id after ≥ 30 frame absence            │
│     - Handles simultaneous multi-person entry          │
│       (distinct track_id within 5 frames)              │
│                                                        │
│  4. Staff filter                                       │
│     - Checks bounding box region against configured    │
│       staff identifier (colour/badge heuristic)        │
│     - Tags track as role=staff → excluded from output  │
│                                                        │
│  5. TrackFrame assembly                                │
│     - Packages: camera_id, frame_id, timestamp,        │
│       list of TrackDetection (track_id, bbox,          │
│       confidence, role)                                │
└────────────────────────────────────────────────────────┘
     │
     │  asyncio.Queue[TrackFrame]  (track_queue)
     ▼
  EventEngine
```

**TrackFrame dataclass:**
```
TrackFrame:
  camera_id:   str
  frame_id:    int
  timestamp:   datetime (UTC)
  detections:  list[TrackDetection]

TrackDetection:
  track_id:    int          # ByteTrack internal ID — never exposed publicly
  bbox:        tuple[float, float, float, float]  # x1,y1,x2,y2 normalised
  confidence:  float
  role:        Literal["visitor", "staff"]
```


### Event Engine Architecture

The `EventEngine` consumes `TrackFrame` objects from `track_queue` and maintains per-visitor state machines. It emits `Event` objects onto `event_queue` (consumed by the API layer for persistence and WebSocket push).

```
asyncio.Queue[TrackFrame]  (track_queue)
     │
     ▼
┌────────────────────────────────────────────────────────────────────┐
│  EventEngine                                                       │
│                                                                    │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  VisitorRegistry                                             │  │
│  │  - Maps track_id → visitor_id                               │  │
│  │  - Assigns new visitor_id on ENTRY confirmation             │  │
│  │  - Re-entry within 300s: reuses original visitor_id         │  │
│  │  - Re-entry after 300s: new visitor_id                      │  │
│  │  - Camera handoff: merges track segments within 10s         │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                    │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  ZoneTracker  (one per visitor)                              │  │
│  │  State: OUTSIDE → IN_ZONE → DWELL_EMITTED                   │  │
│  │  - ZONE_ENTER: on bbox centroid entering zone polygon        │  │
│  │  - ZONE_EXIT: on centroid leaving zone polygon               │  │
│  │  - ZONE_DWELL: after 30s continuous presence in zone        │  │
│  │  - On track loss in zone: emit ZONE_EXIT with last ts        │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                    │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  EntryExitTracker                                            │  │
│  │  - ENTRY: track crosses entry zone boundary inward           │  │
│  │  - EXIT: track crosses entry zone boundary outward           │  │
│  │    + no re-entry within 60s                                  │  │
│  │  - REENTRY: EXIT visitor returns within 300s                 │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                    │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  QueueTracker                                                │  │
│  │  - BILLING_QUEUE_JOIN: visitor enters billing_queue zone     │  │
│  │    queue_position = current depth + 1                        │  │
│  │  - BILLING_QUEUE_ABANDON: visitor exits queue zone           │  │
│  │    without POS correlation within 120s                       │  │
│  │  - Maintains live queue depth counter                        │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                    │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  AnomalyDetector                                             │  │
│  │  - QUEUE_BUILDUP: queue depth > 5 for > 3 minutes           │  │
│  │  - EMPTY_STORE: 0 visitors for > 10 min during hours        │  │
│  │  - UNUSUAL_DWELL: single zone dwell > 15 minutes            │  │
│  │  - CAMERA_OVERLAP_CONFLICT: same track in 2 non-adjacent    │  │
│  │    zones within 2s window                                    │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                    │
│  Emission latency target: ≤ 500ms from triggering condition        │
└────────────────────────────────────────────────────────────────────┘
     │
     │  asyncio.Queue[Event]  (event_queue)
     ▼
  FastAPI API Layer
```

**Event emission latency guarantee:** The engine processes each `TrackFrame` synchronously within its async task. The 500ms budget covers: frame receipt → zone polygon test → state machine transition → event object construction → queue put. No I/O occurs in this path; all I/O (SQLite write, WS push) happens downstream.


### API Architecture (FastAPI)

The API layer runs as a FastAPI application under Uvicorn. It has three responsibilities:

1. **Event consumer task**: Drains `event_queue`, persists events to SQLite, and fans out to WebSocket connections.
2. **REST endpoints**: Serve analytics queries against SQLite.
3. **WebSocket endpoint**: Maintains per-store connection registries.

```
┌──────────────────────────────────────────────────────────────────────┐
│  FastAPI Application                                                 │
│                                                                      │
│  Startup lifespan:                                                   │
│    - Open aiosqlite connection pool                                  │
│    - Start event_consumer asyncio task                               │
│    - Start detection pipeline asyncio task                           │
│    - Start event engine asyncio task                                 │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │  event_consumer task                                           │  │
│  │  while True:                                                   │  │
│  │    event = await event_queue.get()                             │  │
│  │    await db.upsert_event(event)          # idempotent by id    │  │
│  │    await ws_manager.broadcast(event)     # fan-out to WS       │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                                                                      │
│  REST Routers:                                                       │
│    POST   /events/ingest              → events.py                   │
│    GET    /stores/{id}/metrics        → metrics.py                  │
│    GET    /stores/{id}/funnel         → funnel.py                   │
│    GET    /stores/{id}/heatmap        → heatmap.py                  │
│    GET    /stores/{id}/anomalies      → anomalies.py                │
│    POST   /stores                     → stores.py (layout)          │
│    POST   /stores/{id}/transactions   → stores.py (POS)             │
│    GET    /schema/events              → schema.py                   │
│    GET    /health                     → health.py                   │
│                                                                      │
│  WebSocket Router:                                                   │
│    WS     /ws/stores/{id}/events      → websocket/router.py         │
│                                                                      │
│  Middleware:                                                         │
│    - RequestIDMiddleware (UUID v4 per request, propagated to logs)  │
│    - StructuredLoggingMiddleware (JSON log per request)             │
│    - CORSMiddleware (allow frontend origin)                         │
└──────────────────────────────────────────────────────────────────────┘
```

**Request ID propagation:** A `RequestIDMiddleware` generates a UUID v4 `request_id` for every inbound HTTP request, stores it in a `contextvars.ContextVar`, and includes it in all log lines emitted during that request's lifecycle.


### WebSocket Architecture

```
┌──────────────────────────────────────────────────────────────────────┐
│  ConnectionManager  (in-memory, per-process)                         │
│                                                                      │
│  connections: dict[store_id, set[WebSocket]]                         │
│                                                                      │
│  connect(store_id, ws):                                              │
│    1. Validate store_id exists in DB → reject with 4004 if not      │
│    2. Add ws to connections[store_id]                                │
│    3. Send last 50 events for store_id as initial payload            │
│                                                                      │
│  disconnect(store_id, ws):                                           │
│    1. Remove ws from connections[store_id]                           │
│    2. Release resources (no effect on other connections)             │
│                                                                      │
│  broadcast(event):                                                   │
│    1. Look up connections[event.store_id]                            │
│    2. For each ws: await ws.send_json(event.dict())                  │
│    3. On send error: close ws with code 1011, log error             │
│    4. Target: ≤ 200ms under normal load, ≤ 500ms at 50 connections  │
│                                                                      │
│  Ping/keepalive:                                                     │
│    - FastAPI WebSocket uses protocol-level ping frames               │
│    - 60s idle timeout: close with code 1001                         │
│                                                                      │
│  Capacity: ≥ 50 concurrent connections per store                     │
└──────────────────────────────────────────────────────────────────────┘
```

**Initial state payload format:**
```json
{
  "type": "initial_state",
  "events": [ ...last 50 events ordered by timestamp desc... ]
}
```

**Streaming event format:**
```json
{
  "type": "event",
  "data": { ...canonical event object... }
}
```

## Data Models

### Database Schema (SQLite)

All tables use SQLite with `aiosqlite` for async access. WAL mode is enabled for concurrent reads during writes.

```sql
-- ─────────────────────────────────────────────
-- Stores and Layout
-- ─────────────────────────────────────────────

CREATE TABLE stores (
    store_id        TEXT PRIMARY KEY,
    name            TEXT NOT NULL,
    timezone        TEXT NOT NULL DEFAULT 'UTC',
    layout_json     TEXT NOT NULL,   -- full layout JSON blob (zones + cameras)
    created_at      TEXT NOT NULL,   -- ISO 8601 UTC
    updated_at      TEXT NOT NULL
);

CREATE TABLE zones (
    zone_id         TEXT NOT NULL,
    store_id        TEXT NOT NULL REFERENCES stores(store_id) ON DELETE CASCADE,
    name            TEXT NOT NULL,
    zone_type       TEXT NOT NULL CHECK(zone_type IN
                        ('entry','exit','floor','billing_queue','staff_area')),
    polygon_json    TEXT NOT NULL,   -- JSON array of [x,y] normalised coords
    PRIMARY KEY (zone_id, store_id)
);

CREATE TABLE cameras (
    camera_id           TEXT NOT NULL,
    store_id            TEXT NOT NULL REFERENCES stores(store_id) ON DELETE CASCADE,
    position_json       TEXT NOT NULL,   -- {x, y} normalised
    coverage_polygon    TEXT NOT NULL,   -- JSON array of [x,y] normalised coords
    PRIMARY KEY (camera_id, store_id)
);

-- ─────────────────────────────────────────────
-- Visitors and Visits
-- ─────────────────────────────────────────────

CREATE TABLE visitors (
    visitor_id      TEXT PRIMARY KEY,   -- UUID v4, assigned at ENTRY confirmation
    store_id        TEXT NOT NULL REFERENCES stores(store_id),
    first_seen_at   TEXT NOT NULL,      -- ISO 8601 UTC
    last_seen_at    TEXT NOT NULL,
    converted       INTEGER NOT NULL DEFAULT 0,  -- 0 or 1
    visit_count     INTEGER NOT NULL DEFAULT 1   -- incremented on REENTRY > 300s
);

CREATE TABLE visits (
    visit_id        TEXT PRIMARY KEY,   -- UUID v4
    visitor_id      TEXT NOT NULL REFERENCES visitors(visitor_id),
    store_id        TEXT NOT NULL REFERENCES stores(store_id),
    entry_at        TEXT NOT NULL,      -- ISO 8601 UTC
    exit_at         TEXT,               -- NULL until EXIT event
    duration_seconds REAL,              -- computed on EXIT
    is_reentry      INTEGER NOT NULL DEFAULT 0
);

-- ─────────────────────────────────────────────
-- Events (canonical event stream)
-- ─────────────────────────────────────────────

CREATE TABLE events (
    event_id        TEXT PRIMARY KEY,   -- UUID v4, client-supplied (idempotency key)
    event_type      TEXT NOT NULL CHECK(event_type IN (
                        'ENTRY','EXIT','ZONE_ENTER','ZONE_EXIT','ZONE_DWELL',
                        'BILLING_QUEUE_JOIN','BILLING_QUEUE_ABANDON','REENTRY')),
    store_id        TEXT NOT NULL REFERENCES stores(store_id),
    visitor_id      TEXT NOT NULL,
    timestamp       TEXT NOT NULL,      -- ISO 8601 UTC
    camera_id       TEXT NOT NULL,
    attributes_json TEXT NOT NULL DEFAULT '{}',  -- event-type-specific fields
    ingested_at     TEXT NOT NULL       -- server receipt time
);

CREATE INDEX idx_events_store_ts   ON events(store_id, timestamp);
CREATE INDEX idx_events_visitor    ON events(visitor_id);
CREATE INDEX idx_events_type_store ON events(event_type, store_id);

-- ─────────────────────────────────────────────
-- Track Positions (for heatmap)
-- ─────────────────────────────────────────────

CREATE TABLE track_positions (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    store_id        TEXT NOT NULL REFERENCES stores(store_id),
    visitor_id      TEXT NOT NULL,
    camera_id       TEXT NOT NULL,
    timestamp       TEXT NOT NULL,      -- ISO 8601 UTC
    x               REAL NOT NULL,      -- normalised 0.0–1.0
    y               REAL NOT NULL       -- normalised 0.0–1.0
);

CREATE INDEX idx_positions_store_ts ON track_positions(store_id, timestamp);

-- ─────────────────────────────────────────────
-- POS Transactions
-- ─────────────────────────────────────────────

CREATE TABLE pos_transactions (
    transaction_id  TEXT PRIMARY KEY,
    store_id        TEXT NOT NULL REFERENCES stores(store_id),
    timestamp       TEXT NOT NULL,      -- ISO 8601 UTC
    amount          REAL NOT NULL,
    visitor_id      TEXT,               -- NULL if unmatched
    matched         INTEGER NOT NULL DEFAULT 0
);

-- ─────────────────────────────────────────────
-- Anomalies
-- ─────────────────────────────────────────────

CREATE TABLE anomalies (
    anomaly_id      TEXT PRIMARY KEY,   -- UUID v4
    store_id        TEXT NOT NULL REFERENCES stores(store_id),
    anomaly_type    TEXT NOT NULL CHECK(anomaly_type IN (
                        'QUEUE_BUILDUP','EMPTY_STORE',
                        'UNUSUAL_DWELL','CAMERA_OVERLAP_CONFLICT')),
    detected_at     TEXT NOT NULL,      -- ISO 8601 UTC
    severity        TEXT NOT NULL CHECK(severity IN ('low','medium','high')),
    description     TEXT NOT NULL,
    affected_zone_id TEXT               -- nullable
);

CREATE INDEX idx_anomalies_store_ts ON anomalies(store_id, detected_at);
```


### Canonical Event Schema

The canonical event JSON schema (served at `GET /schema/events`) defines the contract for all events:

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "ReIntellect Canonical Event",
  "type": "object",
  "required": ["event_id", "event_type", "store_id", "visitor_id",
               "timestamp", "camera_id", "attributes"],
  "properties": {
    "event_id":   { "type": "string", "format": "uuid" },
    "event_type": { "type": "string",
                    "enum": ["ENTRY","EXIT","ZONE_ENTER","ZONE_EXIT",
                             "ZONE_DWELL","BILLING_QUEUE_JOIN",
                             "BILLING_QUEUE_ABANDON","REENTRY"] },
    "store_id":   { "type": "string", "minLength": 1 },
    "visitor_id": { "type": "string", "minLength": 1 },
    "timestamp":  { "type": "string", "format": "date-time" },
    "camera_id":  { "type": "string", "minLength": 1 },
    "attributes": { "type": "object" }
  }
}
```

| `ENTRY` | _(none required)_ |

## Error Handling

### Detection Pipeline

| Condition | Handling |
|---|---|
| Camera feed unavailable | Log interruption with timestamp; poll for reconnect; preserve active track state and last known positions |
| Detection below confidence/size threshold | Discard silently; no track assignment |
| Track lost < 30 frames | Re-associate on return |
| Track lost ≥ 30 frames | New track_id; emit ZONE_EXIT for any active zones |
| Staff detection | Tag `role=staff`; exclude from all visitor counts and events |

### Event Engine

| Condition | Handling |
|---|---|
| Event persistence failure | Log full payload; retry 3× with exponential backoff (1s, 2s, 4s) |
| Track lost while in zone | Emit ZONE_EXIT with last known timestamp and accumulated dwell |
| Camera overlap conflict | Emit CAMERA_OVERLAP_CONFLICT anomaly; use higher-confidence detection as authoritative position |
| Re-entry within 300s | Reuse visitor_id; emit REENTRY; extend visit record |
| Re-entry after 300s | New visitor_id; new ENTRY; new visit record |

### API Layer

| Condition | HTTP Response |
|---|---|
| Missing/invalid event fields | 422 with per-field error list |
| Unknown store_id | 404 with descriptive message |
| Duplicate event_id (single) | 200 with original event (idempotent) |
| Duplicate event_id (batch) | 200/201 mixed; duplicates included without re-insert |
| Batch with any invalid event | 422 with per-index errors; entire batch rejected atomically |
| Invalid polygon geometry | 422 identifying the specific failing element |
| Malformed date params | 400 with descriptive message |
| start > end | 400 with descriptive message |
| POS timestamp > 24h past or future | 422 with descriptive message |
| Unknown store WebSocket | Close with code 4004 |
| WS push error | Close that connection with code 1011; log; other connections unaffected |
| WS idle > 60s | Close with code 1001 |
| Subsystem health probe failure | GET /health returns 503 with degraded status |

### Database Retry Strategy

Event persistence uses a retry loop with exponential backoff:
- Attempt 1: immediate
- Attempt 2: wait 1s
- Attempt 3: wait 2s
- Attempt 4: wait 4s
- After 4 failures: log with full payload; drop event (do not crash pipeline)

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system — essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

Redundant criteria are consolidated before writing properties: Requirements 14.3 and 15.5 both state the event schema round-trip property (consolidated into Property 1). Requirements 2.8 and 16.2 both state the re-entry visitor_id preservation property (consolidated into Property 6). Requirements 4.2 and 4.3 are complementary but distinct (new vs. duplicate ingestion) and are kept as separate properties.

---

### Property 1: Event Schema Round-Trip

*For any* valid event object (one that passes schema validation without error), serialising it to JSON and deserialising it back SHALL produce an object where every field is equal to the original by value and type.

**Validates: Requirements 14.3, 15.5**

---

### Property 2: Visit Duration Non-Negativity

*For any* sequence of `ENTRY` and `EXIT` events for a given `visitor_id`, the computed `duration_seconds` (the difference between the `EXIT` timestamp and the `ENTRY` timestamp) SHALL always be greater than or equal to zero.

**Validates: Requirements 14.4**

---

### Property 3: Detection Threshold Filtering

*For any* set of raw detections with varying confidence scores and bounding box heights, the Detection Pipeline SHALL output only detections where confidence ≥ 0.5 AND bounding box height ≥ 50 pixels; all detections below either threshold SHALL be absent from the output.

**Validates: Requirements 1.1, 1.8**

---

### Property 4: Staff Exclusion Invariant

*For any* set of detections that includes persons tagged as `role=staff`, none of the staff-tagged detections SHALL appear in the visitor event stream or contribute to any visitor count metric.

**Validates: Requirements 1.5**

---

### Property 5: Zone Dwell Threshold

*For any* visitor track that remains within a single zone, a `ZONE_DWELL` event SHALL be emitted if and only if the continuous dwell duration is at least 30 seconds, and the `dwell_seconds` field in that event SHALL be greater than or equal to 30.

**Validates: Requirements 2.5**

---

### Property 6: Re-entry Visitor Identity Preservation

*For any* visitor who has emitted an `EXIT` event and re-enters the store, if the gap between `EXIT` timestamp and re-entry timestamp is strictly less than 300 seconds, the emitted `REENTRY` event SHALL carry the same `visitor_id` as the original `ENTRY` event, and no new visitor record SHALL be created; if the gap is 300 seconds or more, a new `visitor_id` SHALL be assigned and a new `ENTRY` event SHALL be emitted.

**Validates: Requirements 2.8, 16.2, 16.3**

---

### Property 7: Queue Position Monotonicity

*For any* sequence of visitors joining the billing queue zone, each visitor's `queue_position` in their `BILLING_QUEUE_JOIN` event SHALL equal the number of visitors already in the queue at the moment of their entry plus one (i.e., `queue_position = current_depth + 1`), and `queue_position` SHALL always be a positive integer ≥ 1.

**Validates: Requirements 2.6**

---

### Property 8: Event Ingestion Idempotency

*For any* valid event payload, submitting it to `POST /events/ingest` any number of times SHALL result in exactly one record in the database with that `event_id`; the first submission SHALL return HTTP 201 and all subsequent submissions SHALL return HTTP 200 with the originally persisted event.

**Validates: Requirements 4.2, 4.3**

---

### Property 9: Batch Atomic Rejection

*For any* batch of events submitted to `POST /events/ingest` where at least one event fails schema validation, the entire batch SHALL be rejected (HTTP 422), no events from the batch SHALL be written to the database, and the response SHALL identify each failing event by its zero-based index in the request array.

**Validates: Requirements 4.8**

---

### Property 10: Conversion Rate Correctness

*For any* time window and store, the `conversion_rate` returned by `GET /stores/{id}/metrics` SHALL equal `converted_visitors / unique_visitors` rounded to a decimal between 0.0 and 1.0, and SHALL equal exactly 0.0 when `unique_visitors` is zero.

**Validates: Requirements 5.2**

---

### Property 11: Unique Visitor Count Excludes Re-entries

*For any* sequence of `ENTRY` and `REENTRY` events for a store, the `unique_visitors` count returned by `GET /stores/{id}/metrics` SHALL equal the number of distinct `visitor_id` values with an `ENTRY` event in the time window, and SHALL NOT be inflated by `REENTRY` events for the same `visitor_id` within 300 seconds.

**Validates: Requirements 16.4, 5.2**
